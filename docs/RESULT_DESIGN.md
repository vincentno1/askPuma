## 認真題：預設畫面只有三個主角

1. **一句結論**：12–24 個中文字為設計目標，桌面約 44–64px、手機 30–40px。回答使用者這次具體攻擊，不給 Puma 全面人格評分。內容太長就改寫句子，不縮成難讀小字。
2. **一張本人原文卡**：相關短原句約 30–80 字、最多一處黃色重點標记。保留原句的主詞、否定、條件與時間；必要時可超過目標長度，不能為字數扭曲原話。手機約 22–28px、桌面 28–36px。日期、平台／作者與「開原文」用精簡一行，仍可讀、可按。
3. **一句吐槽**：約 12–28 字，標「旁白」，呼應這題的證據。若吐槽只重複結論、佔用第一屏，就省略。主按鈕是「換個角度再試」。

使用者輸入可保留在簡短的頂部標籤，過長則按開。長篇分析、全部主張與所有來源不預設鋪滿。桌面不強制三欄人物／政策／研究卡；同一議題可有一篇或多篇本人貼文，也可能主要證據是影片或外部文件。

## 按開才看的內容

| 控制 | 展開內容 |
|---|---|
| 看上下文 | 被引用段落的前後文、定位；更完整內容連原貼文，不大量重製全篇 |
| 為什麼這樣判斷 | 一段簡短說明、具體支持／反駁的是哪條主張，仍可質疑之處 |
| 看其他證據 | 其他本人貼文、對方原話、官方資料、研究或新聞，各自日期與原連結 |
| 資料怎麼來的 | 收錄時間、索引署名、查核狀態、缺漏或來源衝突 |

不能把「未核對保存版本」這個影響可信度的狀態藏進按開才看得到的細節；原卡上直接用精簡可見標籤。證據不足／有效質疑也用同樣大字層級，不能只有小字說明。

## 統一元件，內容可變

- 優先顯示本人 PO 文，卡片保留作者、平台、日期、短摘錄與原 URL。競辦网页不是 Facebook 貼文，新聞轉述不是本人 PO 文。
- 可讀原頁、公開資料庫保存文字、影片文字稿、官方紀錄分別標示；沒有相關貼文時直接呈現已找到的證據種類，不模仿社群貼文冒充。
- 不虛構按讚數、留言、認證勾勾。平台嵌入可以後續加；第一版用可控的文字卡與原連結，避免登入／第三方載入阻塞 Demo。
- 完整貼文可連回本人頁面；必要上下文優先展開於站內。多貼文可用「再看一篇」而非同屏堆滿。
- 同一框架用午餐（前後時間）、交通（多方案／摘句）、交流（主詞／條件）驗證；學歷（外部紀錄）測試無本人 PO 文的布局。素材見 [ATTACK_RESEARCH.md](ATTACK_RESEARCH.md)。

## OpenAI 負責濃縮與選證據

流程：自由輸入 → 拆出主張／時間 → 後端檢索少量候選 → 模型分析與選證據 → 後端核對引用 → 畫面大字呈現。

模型產生一句結論、短解釋與旁白；選擇這次來源表內的 sourceId／excerptId。**引言的字句、作者、日期和 URL 由伺服器資料提供，不能由模型重新編寫。** 短結論可以有鋒芒，但長度不能掩蓋證據限制。模型判斷之後仍需核對引用是否真正支持它；結構化輸出不代表已完成事實查核。

濃縮指引：

> 只回答此條主張。用一句繁體中文說清哪裡不成立或還缺什麼；保留時間、條件和主詞。只選可用來源表內的引用。不補寫來源沒有的動機、不把當事人否認當成全面證偽。證據不夠就說不夠。吐槽只評論這次論證，不能增加新的事實指控。

可用的文字語氣，例如「你少看了半句。」、「這題先補證據。」、「這個問題，可以追問。」；都是設計示例，不是對某議題已完成查核的結論。未知題目仍用正常不足結果，避免為了笑點硬選不相關舊文。

## 與現有契約如何接

現有 AuditResult 的 title、summary、roast、claims、limitations，以及 SourceRecord.excerpts 可供初版使用。來源與長分析折疊，不必為視覺再增加一次模型呼叫。一次整理回應可同時有短結論和補充，重試與費用仍受既有上限控制。

若需模型明確選主卡的 sourceId／excerptId，或需要影片時間碼，**由 A 更新 CONTRACTS／型別並通知 B、C、D**。本輪沒有自行增加 API 欄位。未改契約前，可先由伺服器按已核對且相關的證據挑主卡，不讓 B 猜來源。不能把整個檢索 corpus 推給前端。

## 設計與驗收要求

- 保留首页暖白／陶土橘／鮮藍、粗中文與黑色偏移陰影；回答第一屏插畫縮小，讓結論與原句占主位。
- 載入時可用一般「正在找原文」，只有真的執行該動作才顯示相應提示。不用假進度條裝搜尋。
- 三個不同議題使用同一結果框架；不能 hardcode 針具、WHO、固定三份來源或固定「Puma 是對的」。
- 查核未知、來源衝突、合理質疑、長引用、無貼文只有影片／官方紀錄、手機展開補充、API 失敗均需驗收。
