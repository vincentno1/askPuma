# 三題 Demo 與案例交付規格

2026-10-04 最新使用者指定順序：**發針頭給吸毒者 → 爆炸頭 → 營養午餐**。本文件是待實作／查核規格，不代表答案已生成或來源已升級 checked。先照 IMPLEMENTATION_PLAN 與 CONTRACTS v2 接入同一 API。

## 01：發針頭給吸毒者

- canonicalQuery：「發針頭給吸毒者，是鼓勵吸毒嗎？」
- 互動：factual。大字候選：「這是減害政策，／台北也有。」這句支持的範圍是清潔針具服務，不是所有毒品政策。
- 旁白候選：「你以為找到黑料，結果找到市府服務。」不追加市長不懂、說謊、反對針具等無證主張。
- 主卡候選：Puma 2026-10-03 16:01:23 台灣時間 Threads，https://www.threads.com/t/DeBlQ6YlHK1 。本輪 JSON 已確認有該筆保存文字，原頁工具無法開啟，預設 imported_unchecked；可摘「叫做針頭交換和／美沙冬治療計劃」，截取依原段落與前後文，不由模型改寫。
- 主卡保留平台 Threads，不能為了符合圖把它寫成 Facebook。若原頁不可讀，直接顯示「保存版本・原頁待核對」，並有索引保存頁與原連結。結論需要官方政策另作支持，不能只靠未核對貼文。
- 佐證：台北市清潔針具交換點資料 [S03](https://data.taipei/dataset/detail?id=5e53353a-4799-4b02-8922-cf81bb6fbf95)，WHO [S04](https://www.who.int/westernpacific/publications/i/item/9789240116214)。開工重開核對；更新日期不是政策首創日期。
- 上下文：[2014 原文 S01](https://www.thinkingtaiwan.net/content/3055) 不只含針具，也有供毒措辭。原文章節與研究限制放展開區；在回答中以短句可見「針具交換與提供毒品需分開判斷」。不能因這題比較容易就抹去另一段。
- 如官方來源未核對：先降為「這題先拆開：針具不等於供毒」，標來源待核對，不硬用確定判定。沒有原話可用則呈現官方文件卡，不造人物卡。

必測反例：「他2014年不是說提供毒品嗎？」不能精確匹配針具案例；「蔣萬安反對針具交換嗎？」不能靠市府服務存在答是；「針具交换能杜絕毒品嗎？」不能答能。

## 02：為什麼要留爆炸頭

- canonicalQuery：「為什麼要留爆炸頭？」
- 互動：playful，verdict=null，无事實 claims，無人物引言卡。
- 大字：「你以為是髮型，／其實是戰鬥型態。」
- 旁白：「別人出門整理頭髮，他出門裝備主角光環。」
- 圖：沿用 03-v2 原創貓的爆炸頭、藍拳套、綠背心；使用獨立資產，非全頁 PNG。
- 「玩梗模式」「動漫旁白，非本人說法」保持可見。
- 折疊說明：聯想到《ONE PIECE》魯夫戴爆炸頭的橋段；這是本站創作，不是證明髮型有超能力或 Puma 真正留髮動機。確切台詞沒核對就不要用引號說是動漫原句。
- 可參考 [授權遊戲合作公告](https://prtimes.jp/main/html/rd/p/000000112.000071247.html)、[官方第217集頁](https://one-piece.com/anime/217/index.html)，只支持橋段／角色識別，不支持 Puma 的心理動機。
- 「想看認真答案」送出不同事實問題；若沒有本人說明，回答無法確認原因，不把笑話套過去。

必測反例：「他親口說過留爆炸頭是學魯夫嗎？」走 factual；「爆炸頭是不是證明他不懂市政？」走 mixed／factual，玩笑不能取代市政證據。

## 03：營養午餐

- canonicalQuery：「Puma 一下免費、一下自費，營養午餐髮夾彎？」
- 互動：factual。視覺候選大字：「免費保底，／自費加菜。」在補齊來源前，這只可說明目前主張，不證明過去完全一致。
- 旁白候選：「先看菜單，再決定要不要掀桌。」即使歷史未核對也不偷渡『從未改變』。
- 主卡候選：2026-10-02 11:43:24 台灣時間 Instagram [P01](https://www.instagram.com/p/Dd-i8hVEjO_/)；保存文字本輪已確認，短摘「保留學校與家長討論自費加菜的彈性」。原頁未逐筆查驗則 imported_unchecked；不能把 IG 寫成 Facebook。
- 補充：[本人官網完整回應](https://puma.taipei/fact-checks/fact-check-19)，核對目前方案、免費的支持範圍；官網自我澄清不是過去一致性的獨立證明。
- 歷史比較需補 9/17 完整原話／影片與日期、9/20 說明、10/2 新方案。[9/20 CNA](https://www.cna.com.tw/news/aloc/202609200089.aspx)、[10/2 CNA](https://www.cna.com.tw/news/aloc/202610020077.aspx) 是報導／轉述，不當本人發文。
- 問的是『髮夾彎』時，若缺最早完整語境，可見限定：「目前方案可確認；早期完整發言尚待核對。」verdict 依實際證據 missing_context／insufficient_evidence，不能確定宣稱從未改變。
- 如果太晚補不齊：Demo 可改問「免費午餐還要自費加菜，不矛盾嗎？」并明確說這是目前方案題，不能無聲改寫原問題後宣稱歷史質疑被證偽。由 Vincent 確認最終展示問題。

必測反例：「他9月17日到底說什麼？」不能直接套目前方案；「目前方案成本多少？」找不到數字則不足；「他反對免費午餐嗎？」保留否定与時間條件，不用主題名快取。

## 三題都要達到的品質

1. 大字 1–2 行；一句旁白；事實題一張主卡，平台／日期／來源狀態／原連結可見；其他內容折疊。
2. 名稱、日期、原句、連結、摘錄前後文全部逐筆核對；未核對就保留標籤。文字精修不刪不利條件。
3. 卡片、展開、重試、認真答案是真 DOM 可操作；1440px／390px 沒有水平溢出。
4. 精確案例回答的回應速度目標 <1 秒（另計網路與 cold start，待測）；不得用假 loading 宣稱即時 AI。自由題延遲以實测記錄。
5. 開工後至少真正呼叫 API 生成／整理資料，再由人驗收可发布案例；fixture 始終只能开发用。
6. 試兩個未收錄提問与兩個反例，證明任意題不是都回這三題。來源不足是正常結果。

## 夥伴補題格式（先用文字即可）

每題一份 Markdown 或一段訊息：題目／想吐槽的點／事實或純玩梗／原來源URL＋日期／短原句／前後文／希望的大字答案／希望的旁白／不能推論什麼／核對狀態。可用 docs/case-intake/ 保存。不要要夥伴編寫 API schema 或讓他們自行把 draft 改 ready。

編輯負責人先查原文、決定範圍、選 excerpt ID；A／D 落成 prepared case。來源沒有核對可先當題目建議，但不能直接公開確定事實。角色与来源可靠度都按 CONTRACTS。
