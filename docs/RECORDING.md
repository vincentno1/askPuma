## 今天用十分鐘確認錄得出來

1. 使用者安裝所選工具並處理 macOS 螢幕錄製、攝影機與麥克風權限。權限修改可能要重啟工具；不要明天錄影時才第一次打開。
2. 選一個普通網站或規劃文件，錄 20 秒：前鏡頭＋旁白＋點擊＋捲動。不用 askPuma 預先完成的 UI。
3. 加一次自動或手動放大，匯出 MP4，用 QuickTime 播放。
4. 核對臉和螢幕都有錄到、聲音同步清晰、中文字可讀、沒有不能接受的浮水印、匯出沒有付費或格式阻擋。
5. 成功後保留設定。若工具無法完成，切換上述備案；不為了錄影安裝一串未測插件。

今天這項測試是錄影工具準備，不是作品實作。工具訂閱獨立於 OpenAI API 預算；本文件不代表已授權自動購買。

## Screen Studio 建議設定與操作

- 錄製浏覽器視窗，鏡頭選 MacBook 內建前鏡頭，麥克風優先使用已測過的耳機／外接麥克風。先聽 20 秒樣本再決定；現場人多時旁白清楚比背景音樂重要。
- 先錄 16:9，輸出 1080p／30fps MP4；如果當時 UI 不提供某個選項，採它支持的接近設定。不要為一分鐘影片輸出大檔 4K。
- 人像放右下或左下，寬度先抓畫面約 15%，依卡片位置調整；不蓋住引文、來源按鈕或 verdict。後製可重新擺放鏡頭。
- auto zoom 依點擊位置安排；長段落只捲動不點擊時，可能不會自動放到你要的位置，需手動加 zoom。
- 一分鐘最多 2–3 次放大：原文關鍵段落、官方政策證據、最後結論。前後保留全景，放大後停留幾秒讓人看得完。
- 避免每個 click 都放大，避免先移到人像再移到文件的頻繁漂移。最後檢查放大是否切掉日期或上下文。

官方操作文件：[攝影機與麥克風](https://screen.studio/guide/webcam-microphone)、[自動放大](https://screen.studio/guide/auto-zoom)、[手動放大](https://screen.studio/guide/manual-zoom)、[權限](https://screen.studio/guide/setting-up-permissions)、[匯出設定](https://screen.studio/guide/explanation-of-export-settings)、[系統要求](https://screen.studio/guide/system-requirements)。

## 免費方案怎麼錄

Recordly：先確認所下載版本能錄螢幕、前鏡頭與聲音。錄好後在時間軸保留真正要展示的點擊與放大，刪除多餘放大；匯出 MP4 後再播一次。功能在持續更新，不能只看產品頁就保證本機毫無問題。

OBS：建立一個「全景」場景，加入 macOS Screen Capture、Video Capture Device 和 Audio Input Capture；再建立一個「證據近景」場景，裁切／放大證據區、保留人像。用快捷鍵在兩場景切換。需要預先固定瀏覽器視窗與證據卡位置；內容滾動後裁切可能失準。沒有時間編輯時，寧可清楚全景＋少量手動切換。

OBS 官方：[來源指南](https://obsproject.com/kb/sources-guide)、[macOS 螢幕擷取](https://obsproject.com/kb/macos-screen-capture-source)。

## 55–58 秒腳本與操作

使用 [三題正式腳本](DEMO_CASES.md)，取代舊單題針具錄影。已整理／已儲存標籤保持可見；若剪去真正的 API 等待，轉場標「略去等待」，不聲稱即時完成。原文、日期、核對狀態与限定条件不能被 zoom 裁掉。

## 最後半小時安排

| 時間 | 工作 |
|---|---|
| 14:20–14:30 | 網站提交前準備視窗、字級、人像位置、腳本、靜音通知；先完成作品提交 |
| 14:30–14:35 | 錄兩次完整操作，第二次只修最必要問題，不無限重錄 |
| 14:35–14:40 | 選最好一段、剪頭尾／等待、調 2–3 個 zoom、匯出並播放檢查 |
| 14:40–14:50 | 上傳 YouTube，確認播放、可見性與網站連結，提交影片網址 |
| 14:50–15:00 | 上傳／處理／提交失敗的緩衝。截止要求是已提交可看的連結 |

錄影前關閉不相關分頁與通知，用演示瀏覽器視窗；不要錄到 Firebase／API 金鑰畫面。字幕不是必需，背景音樂不是必需，剪映／DaVinci 等第二套剪輯軟體也不是必需。今晚測匯出比明天追求大量剪輯效果更有用。
